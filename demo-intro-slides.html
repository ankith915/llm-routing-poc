01 — The problem

Every request goes to the best model. So every request pays the best model's price.

It is the safe default, and it quietly overpays — most questions in a real workload never needed the expensive model to answer them correctly.

The objective isn't to always use the cheapest model. It's to use the cheapest model that can satisfy the requirements of the request.

02 — How it works

Three strategies, one identical set of questions.

Baseline

No routing

Every question goes to the premium model. This is what most systems do today.

100% premium

Strategy B

Rule-based

Keyword heuristics sort each question into simple, medium or hard, then map to a tier.

deterministic · free to run

Strategy C

Intelligent

A small model assesses the request; code then picks the cheapest tier meeting every constraint.

generalises to unseen queries

The model advises, code decidesThe router returns an assessment — complexity, reasoning need, context size, quality bar. Code turns that into a minimum capability level, then takes the cheapest tier clearing it that also fits the context window and latency limit.
Measured on both axes18 questions across three difficulty bands, each with a predefined expected answer. Every response is graded 1–5, so cost savings are never claimed without checking quality.

04 — Token reduction

Two levers, measured on the same questions.

Already banked · context format vs naive JSON dump

−25.8%

39,495 → 29,298 context tokens across the 18 demo queries. Zero quality risk — it is how the pipeline formats telemetry today.

TOON format evaluated: +18–28% more tokens than this on our data. Rejected.

Headroom compression · on vs off, 108 graded requests

−17.6% tokens

≈ −10% cost per request on the premium tier. But quality depends entirely on which model reads the compressed context:

gpt-4.1 · premium4.59 → 4.61
gpt-oss-120b · medium4.73 → 4.50
gpt-oss-20b · cheap4.64 → 3.57
Compress above the cheap tier — never below it.

Headroom's only transform on this data folds timestamps. A frontier model reassembles them; a 20B model misreads the incident timeline. The two levers interact — the next step is tier-aware compression, not a global switch.
